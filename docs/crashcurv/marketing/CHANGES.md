# Capture-session finding

The packaged app completed the 1K Cherry Wood UV/Triplanar save/reopen check and exited cleanly. In the later interactive capture session, one 64×64 bake of seven maps completed, including GPU AO/thickness. Starting a subsequent 256×256 bake in the same edited project produced a native crash report after cache release. The 5 November follow-up identified invalid corner-normal fan indexing after coincident vertices collapse. Bake meshes now store float corner normals directly. The owned capture process group was stopped; no other process was touched. Both store drafts now distinguish the tested local fix from the older packaged AppImage. The fixed local build passed 64 → 256 → 1024 → 256 → 64 → 1024 → 64 for all seven maps through the workspace, including GPU AO/thickness and OIDN. No new 4K/8K validation is claimed. Full results and limits are in [REPORT-crashcurv.md](../REPORT-crashcurv.md). See `evidence/ui-first-run.log`, `evidence/mesh-rebake-crash.txt`, `evidence/bake-settings.png` and `evidence/bake-64-complete.png`.
